## The system fonts

**San Francisco (SF)** — sans serif. Variants: SF Pro, SF Compact, SF Arabic, SF Armenian, SF Georgian, SF Hebrew, SF Mono.
**New York (NY)** — serif, designed to work alongside SF.

Nine weights: Ultralight, Thin, Light, Regular, Medium, Semibold, Bold, Heavy, Black.

> In general, avoid light font weights. Prefer Regular, Medium, Semibold, or Bold; Ultralight, Thin and Light are hard to read, especially when text is small.

## Emphasized weights

Every style has an emphasized variant, used consistently across all size categories:

- **Bold** — Large Title, Title 1, Title 2
- **Semibold** — Title 3, Headline, Body, Callout, Subhead, Footnote, Caption 1, Caption 2

In SwiftUI that is `.font(.title.bold())` or `.fontWeight(.semibold)`; the system already applies the right emphasis when you use `.bold()` on a semantic style.

## Platform default and minimum sizes

For custom type styles, as published by Apple:

| Platform | Default | Minimum |
|---|---|---|
| iOS, iPadOS | 17 pt | 11 pt |
| macOS | 13 pt | 10 pt |
| tvOS | 29 pt | 23 pt |
| visionOS | 17 pt | 12 pt |
| watchOS | 16 pt | 12 pt |

If you use a thin weight, go larger than the minimum.

## Using these numbers correctly

Use the tables to **check** a design, not to write code. Semantic styles get Dynamic Type for free:

```swift
Text("Title").font(.title2)
Text("Body copy").font(.body)
Text("Caption").font(.caption)
```

Modify a built-in style with symbolic traits rather than replacing it:

```swift
Text("Emphasis").font(.body.weight(.semibold))
Text("Tight").font(.body).lineSpacing(-2)   // adjust leading, keep the style
```

The size categories above map to `DynamicTypeSize` in SwiftUI (`.xSmall` … `.xxxLarge`, `.accessibility1` … `.accessibility5`) and `UIContentSizeCategory` in UIKit. Test with:

```swift
#Preview {
    ContentView().environment(\.dynamicTypeSize, .accessibility5)
}
```

Clamp only where the layout genuinely cannot adapt, and clamp as high as you can bear:

```swift
.dynamicTypeSize(...DynamicTypeSize.accessibility3)
```

Clamping at `.large` is not accessibility support; it is opting out.

## Custom fonts

A custom font gets none of this automatically. To make it behave:

**SwiftUI** — `@ScaledMetric` for sizes and spacing, `.custom(_:size:relativeTo:)` for the font:

```swift
@ScaledMetric(relativeTo: .body) private var iconSize: CGFloat = 24

Text("Hello")
    .font(.custom("Inter", size: 17, relativeTo: .body))
Image(systemName: "star")
    .frame(width: iconSize, height: iconSize)
```

**UIKit** — `UIFontMetrics`:

```swift
let base = UIFont(name: "Inter", size: 17)!
label.font = UIFontMetrics(forTextStyle: .body).scaledFont(for: base)
label.adjustsFontForContentSizeCategory = true
```

Also implement the Bold Text accessibility setting, which system fonts honor automatically: read `UIAccessibility.isBoldTextEnabled` or `\.legibilityWeight` and select a heavier face.
